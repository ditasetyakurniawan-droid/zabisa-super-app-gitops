# Zabisa GitOps

Dedicated desired-state repository for the Zabisa DT environment. This follows
the existing `tropical-management-gitops` separation: application source is
owned by `zabisa-super-app`, immutable container images are stored in Harbor,
and ArgoCD reads only this repository.

## Layout

```text
bootstrap/argocd-application.yaml
apps/zabisa/overlays/dt/
  kustomization.yaml
  SOURCE_REVISION
  manifests/*.yaml
```

The DT overlay is generated by the application repository pipeline. Do not
edit generated manifests or image tags manually. `SOURCE_REVISION` and all
Zabisa workload tags must contain the same full source Git SHA.

## Delivery flow

1. GitHub validates source quality and browser E2E.
2. Jenkins runs private Sonar and digest-pinned Trivy.
3. Jenkins builds and pushes nine immutable images to
   `harbor-dt.co.id/devops-apps/zabisa`.
4. Jenkins verifies Harbor digests and commits the rendered overlay here.
5. An operator reviews this repository diff.
6. ArgoCD migration and sync are started separately and manually.

Validate locally:

```bash
./scripts/verify-gitops.sh
```

Committing desired state does not itself authorize a database migration or an
ArgoCD sync.
